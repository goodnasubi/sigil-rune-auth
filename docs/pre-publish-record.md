# 公開前の記録（ADR 0060 段 5）

この文書は [ADR 0060][adr0060] 決定 4 の段 5 の記録です。[ADR 0020][adr0020] 決定 3 の **G2（段階の完了の確認）** の記録と、**G3（公開前のレビュー）で所有者へ提示する 6 項目**を残します。コードは変えません。

## G2 は外部公開を承認しない

**G2 は外部公開を承認しません。** G2 は、実装者が「段階の完了の確認」として、検査・試験が入っていることを確かめる関門です（ADR 0020 決定 3）。外部公開してよいかを決めるのは **G3 の報告を読んだ所有者** であり、所有者が承認しない限り外部公開しません。

- 外部公開とは、所有者が管理しない網から Sigil のサービスへ到達できる場所に置くこと、または実在の利用者のデータを扱うことです。CI、ローカルのコンテナでの試験、リポジトリを公開することは含みません（ADR 0020）。
- 本文書は G3 を実施したことの記録ではありません。G3 は、実装者と別のセッションがリポジトリと ADR だけを読んで行い、報告を `docs/security/` に日付と対象コミットつきで置きます。まだ行っていません。

## G3 で所有者へ提示する 6 項目

ADR 0060 の脅威の表は、これらを「G3 で所有者へ提示する」と定めています。どれも現在の設計で意図して受け入れている制約で、実装の欠陥として直す対象ではありません。所有者は、外部公開の可否を決める前にこれらを読みます。

### 1. 時計の監視

- **内容**: セッションの期限、トークンの発行時刻と期限、抑制の窓は、すべて時計の値で決まります。時計が巻き戻ると、期限切れのセッションが再び有効になり、抑制の窓も延びます。時計が進みすぎると、有効なセッションが早く失効します。
- **現状**: 時計を取得できないときは、ログインとトークン発行が失敗します。時計の巻き戻りや飛びを検出する仕組みはありません。
- **所有者へ**: 運用で時計（NTP など）を監視するか、巻き戻りの検出を実装の項目として加えるかを決めてください。

### 2. TLS 終端と内部網

- **内容**: TLS は前段（sigix）で終端します。`sigil-shield-tls` は名前だけで、実装ではありません。サービス自身は平文の HTTP を話します。`Secure` cookie は TLS を前提にします。`X-Forwarded-For` は信頼するプロキシ（`trusted_proxies`）からの要求だけで使います。
- **現状**: 前段と本サービスの間の経路は内部網として信頼します。内部網で盗聴や、前段を通らない直接の接続ができると、パスワード・cookie・トークンが平文で見え、`X-Forwarded-For` を偽れます。
- **所有者へ**: 前段と本サービスの間をどの網に置くか、直接の接続をどう遮断するかを決めてください。TLS 終端は本リポジトリの範囲外です。

### 3. 鍵の交換運用

- **内容**: アクセストークンの鍵（audience ごとの 32 バイト）は、ADR 0037 の制約を引き継ぎ、無停止で交換する仕組みがありません。個別のトークンの失効もありません（既定の有効期間は 300 秒、範囲は 60〜3,600 秒）。
- **現状**: 鍵を交換すると、発行済みのトークンはすべて検証に失敗します。鍵が漏れた場合は、鍵を交換して有効期間が尽きるのを待つ運用になります。
- **所有者へ**: 交換の手順、頻度、漏えい時の対応を運用として決めてください。無停止の交換は ADR 0037 の改訂を要し、本段の範囲外です。

### 4. ログイン抑制の限界

- **内容**: 抑制は単一プロセスの中だけで行います（利用者ごとに 15 分に 5 回失敗で 15 分拒否、接続元 IP ごと、容量 1,024）。KV に原子的な加算がないため、KV には置きません。単一のインスタンスを前提にします。
- **現状**: 再起動で状態が消え、抑制がやり直しになります。複数のインスタンスでは、インスタンスごとに別々に数えるため、上限が実質的に増えます。前段が `X-Forwarded-For` を送らない場合の接続元の扱いも、前段の設定に依存します。同時 PBKDF2 数の上限は未実装です。
- **所有者へ**: 単一インスタンスでの運用を前提にするか、共有の状態を持つ抑制を別の ADR で決めるかを決めてください。

### 5. 保留リストの喪失

- **内容**: ログアウトで KV の `DELETE` の結果が分からないとき、セッション ID を保留リストに入れて 503 を返します。保留リストはプロセスの中だけにあり、再起動で消えます。これは ADR 0060 が受け入れた制約です。
- **現状**: 保留中のまま再起動すると、その失効は確定せず、セッションは絶対寿命（既定 8 時間）まで有効なままになりえます。利用者の世代の更新で全セッションを失効させる手段は残ります。
- **所有者へ**: この窓を許容するか、保留リストを永続化するか（KV が使えないときに何へ書くかも含む）を決めてください。

### 6. PBKDF2 の反復回数

- **内容**: PBKDF2-HMAC-SHA256 の反復回数は、ADR 0024 / 0020 により 4096〜100000 に固定され、初期の設定は上限の 100,000 です。ADR 0060 の起草時に挙げた OWASP の目安は 600,000 回で（再確認していません）、現在の上限はそれを下回ります。
- **現状**: 上限を上げるには ADR 0024 の改訂が要ります。固定した処理系では、100,000 回の導出に評価器で約 65 秒、ネイティブで約 38 秒かかるため、ログインの遅さと同時実行の上限に直結します（試験は 4096 回で実行しています）。
- **所有者へ**: 現在の上限で公開してよいか、上限の引き上げ（ADR 0024 の改訂と処理速度の改善）を公開の条件にするかを決めてください。
